# Файл для отметок об использовании LLM

В ходе работы над проектом использовался ChatGPT 5 и Codex для работы с архетектурой, а также фронтенд и бекенд разработки.

1. **ChatGPT 5**

   - **Промт:**

     `У меня есть веб-приложение на Nuxt 3 и Vue 3. Объясни, как лучше организовать его архитектуру: где должны находиться страницы, компоненты, типы данных, состояние приложения и вычислительная логика.`

   - **Ответ:**

     Модель предложила разделить проект на несколько уровней:

     - `pages/` — маршруты и компоновка страниц;
     - `components/` — независимые Vue-компоненты;
     - `stores/` — глобальное состояние Pinia;
     - `types/` — TypeScript-интерфейсы;
     - `utils/` — вычисления, не зависящие от интерфейса;
     - `assets/` — общие стили;
     - `public/` — статические файлы.

     Эта структура была использована в EcoFisher. Основная страница собирает интерфейс из компонентов, Store управляет состоянием, а вычислительная логика вынесена из Vue-компонентов.

2. **ChatGPT 5**

   - **Промт:**

     `Как во Vue-приложении правильно отделить вычислительную логику от компонентов, чтобы компоненты отвечали только за отображение и пользовательский ввод?`

   - **Ответ:**

     Модель рекомендовала оформить вычисления как чистые TypeScript-функции: они получают состояние и параметры, а затем возвращают новое состояние без обращения к DOM и Vue-компонентам.

     В EcoFisher вычислительное ядро размещено в `utils/simulation.ts`, контракты данных — в `types/simulation.ts`, а компоненты получают готовые данные через Pinia Store. Благодаря этому код интерфейса не содержит основной логики симуляции.

3. **ChatGPT 5**

   - **Промт:**

     `Как организовать Pinia Store для симулятора, в котором должны быть запуск, пауза, ручной шаг, сброс, изменение скорости и сохранение истории состояний?`

   - **Ответ:**

     Модель предложила хранить в Store:

     - текущие параметры;
     - текущее состояние;
     - историю для построения графиков;
     - признак запущенной симуляции;
     - скорость воспроизведения;
     - идентификатор таймера.

     Команды управления были оформлены отдельными действиями Store. Компоненты вызывают эти действия и не управляют таймером напрямую.

4. **ChatGPT 5**

   - **Промт:**

     `Как подключить Apache ECharts к Vue 3 так, чтобы графики автоматически обновлялись при изменении данных в Pinia и корректно меняли размер вместе с окном браузера?`

   - **Ответ:**

     Модель предложила создавать экземпляры графиков после монтирования компонента, обновлять их параметры через реактивное наблюдение за историей Store и вызывать `resize` при изменении размера окна.

     В `SimulationCharts.vue` данные преобразуются в серии ECharts, а экземпляры диаграмм уничтожаются при размонтировании компонента. Это предотвращает утечки памяти и повторное создание графиков на каждом шаге.

5. **ChatGPT 5**

   - **Промт:**

     `Как проверить и запустить существующий Nuxt-проект локально? Также хочу использовать Vue DevTools для просмотра компонентов и состояния приложения.`

   - **Ответ:**

8. **ChatGPT 5**

   - **Промт:**

     `Какие файлы Nuxt-проекта нужно хранить в GitHub, а какие не надо добавлять в репозиторий? Как правильно настроить gitignore?`

   - **Ответ:**

     Модель объяснила, что в репозитории должны находиться исходный код, `package.json`, lock-файл и конфигурация проекта. Каталоги зависимостей, результаты сборки, кеш, системные файлы и локальные переменные окружения должны исключаться через `.gitignore`.

     Перед публикацией были отдельно проверены `node_modules/`, `.nuxt/`, `.output/`, Python-кеш и локальные служебные каталоги.

9. **ChatGPT 5**

   - **Промт:**

     `Можно ли развернуть Nuxt 3 приложение на GitHub Pages без отдельного сервера и без потери интерактивности? Как настроить автоматическую публикацию?`

   - **Ответ:**

     Модель объяснила, что приложение может быть статически сгенерировано, если вся рабочая логика выполняется в браузере и проект не зависит от серверного API.

     Был подготовлен GitHub Actions workflow, который:

     1. устанавливает Node.js;
     2. устанавливает зависимости через `npm ci`;
     3. запускает генерацию Nuxt;
     4. задает `baseURL` репозитория;
     5. публикует каталог `.output/public` на GitHub Pages.
